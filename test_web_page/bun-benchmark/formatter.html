측정 방식 및 재현 (Methodology)

  • 측정 도구: hyperfine 쓰기 모드(--write), 워밍업 1회. 매 반복마다 --prepare를 통해 코퍼스를 초기 상태로 원복하며, 원복 시간은 측정에서 제외합니다.
  • 코퍼스 구성: test_web_page 저장소의 git 추적 소스(HTML, CSS, JS, JSX, TS, TSX, Vue, JSON). large 코퍼스는 이를 40회 복제하여 대규모 프로젝트를 모사했습니다.
  • Biome 옵션: 실험적 HTML 포맷터를 활성화하고, Prettier와 규격을 맞추기 위해 indentStyle: space, selfCloseVoidElements: always 등을 지정했습니다.
  • 재현 명령: bun install && bun run bench 실행 시 벤치마크가 재수행되고 formatter-results.json이 업데이트됩니다.

성능 및 호환성 분석 (Engineering Notes)

  • 병렬 처리 아키텍처: Prettier는 Node.js 단일 스레드로 동작하는 반면, Biome(Rust)과 bun fmt(Rust, v1.4.0+)는 네이티브 스레드 풀을 통해 모든 CPU 코어를 활용하므로 처리량에서 큰 격차가 발생합니다.
  • 코퍼스 규모와 Throughput: 파일 수가 적은 원본 1벌(140개)에서는 프로세스 기동(Startup) 오버헤드 비중이 크지만, 대용량 코퍼스(5,600개)에서는 I/O 및 파서의 순수 Throughput이 드러납니다.
  • bun fmt: main 브랜치 canary 빌드임에도 검증된 140개 파일 전원에 걸쳐 Prettier와 100% 바이트 일치를 기록했습니다.
  • Biome: 전반적으로 높은 호환성(97.9%)을 보이나, HTML 및 Vue/TSX 일부 엣지 케이스에서 미세한 공백/줄바꿈 차이가 존재합니다.
