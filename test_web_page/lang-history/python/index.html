Language History

버전별 굵직한 변화(문법 · 표준 라이브러리 · 툴체인 · 런타임)와, 서드파티 툴이 난립하다가 빠르거나 공식 내장된 하나로 수렴하는 흐름을 한눈에 봅니다. 항목을 클릭하면 아래에서 배경과 이유를 볼 수 있어요.

Python

uv 2024-02 pip 대체 → 2024-08 프로젝트 · 파이썬 · 툴 통합

What
Rust 로 쓴 단일 바이너리. pip · pip-tools · virtualenv · pipenv · poetry · pyenv · pipx 의 역할을 uv 하나가 담당. "Cargo for Python" 이 명시된 목표.
Why now
  • 표준이 먼저 정착했음 — PEP 517/518 (2017) 로 빌드가 분리되고 PEP 621 (2020) 로 메타데이터가 [project] 로 통일되자, 툴은 "표준을 빠르게 구현하는 것" 만 남음. pip 의 새 resolver (20.3, 2020) 는 정확해졌지만 느렸음
  • ruff (2022) 가 "Python 툴을 Rust 로 다시 쓰면 10–100× 빨라지고 사람들이 갈아탄다" 를 증명하고 Astral 이 VC 자금 (2023-04) 으로 같은 팀을 패키징에 투입. 첫 벤치는 pip 대비 캐시 없이 8–10×, 웜 캐시 80–115×
  • Rye (Armin Ronacher, 2023) 가 "하나의 툴" 수요를 먼저 보여줬고 Astral 이 2024-02 인수 → 2024-08 uv 0.3 에 lockfile · uv python · uvx · PEP 723 스크립트를 넣으며 Rye 를 흡수 (Rye 는 2025-02 개발 종료)
Replaced
pipx — conda 는 네이티브 바이너리 생태계로 별도 유지
Numbers
Python Developers Survey 2024: 출시 1 년 만에 11% (Simon Willison: "notable achievement") · PyPI 2026-09 월간 다운로드 uv 128M vs pip 407M · GitHub 90.9k stars (2026-10) · 2026-03 Astral 이 OpenAI Codex 팀에 합류, 오픈소스 유지 선언

pipenv · poetry · pdm 2017 – 2024 · "pip 위의 한 겹" 세대

What
lockfile · 가상환경 · 의존성 그룹을 한 명령으로 묶은 서드파티 프로젝트 관리자. 각자 다른 lock 형식 (Pipfile.lock / poetry.lock / pdm.lock).
Why now
  • pipenv (2017-01, Kenneth Reitz): PyPA 가 문서에서 "공식 권장" 으로 소개해 급부상했지만 resolver 가 느리고, 2018-11 → 2020-05 18 개월간 릴리스가 끊기며 신뢰를 잃음. 지금도 유지보수되지만 설문 8% (2024)
  • poetry (2018-02): 깔끔한 UX 로 2020–2023 사실상 표준. 그러나 [tool.poetry] 독자 메타데이터를 고수해 PEP 621 [project] 를 2.0 (2025-01) 에서야 지원 — 표준에 늦은 사이 uv 가 표준 위에서 10× 빠르게 등장
  • pdm (2020): PEP 621 을 가장 먼저 따랐지만 PEP 582 (__pypackages__) 에 베팅했다가 2023 년 PEP 가 거부됨. 셋 다 Python 으로 쓰여 Rust 기반 uv 의 속도를 따라갈 구조가 아니었음

venv · ensurepip 3.3 (2012-09) · 3.4 (2014-03) 흡수

What
가상환경 (python -m venv) 과 pip 번들 (python -m ensurepip) 이 표준 설치본에 포함. 설치 직후 "pip 이 없다" 문제가 사라짐.
Why now
  • easy_install (setuptools, 2004) 은 제거 · 버전 고정이 안 돼 pip (2008) 이 대체했지만, 정작 pip 을 설치하려면 easy_install 이 필요한 닭-달걀 문제가 2013 년까지 지속
  • virtualenv (2007, Ian Bicking) 가 사실상 필수였으나 인터프리터 내부를 복사하는 해킹이라 버전마다 깨짐 → PEP 405 로 인터프리터가 직접 지원 (pyvenv.cfg)
  • 2.7 이 2020 년까지 살아 있어 virtualenv 는 "2.7 겸용" 으로 오래 남음. 2024 설문에서도 venv 62% · virtualenv 25%. uv 는 venv 형식을 그대로 쓰되 생성 속도를 80× 로
Replaced

uv python 2024-08 → · pyenv (2012) 의 역할 흡수

What
uv python install 3.14 또는 .python-version · requires-python 만 적으면 uv 가 해당 버전을 자동 다운로드. Go 의 go.mod toolchain 과 같은 모델.
Why now
  • pyenv (2012) 는 rbenv 를 옮긴 셸 shim 방식 — 소스를 직접 컴파일해 설치에 수 분, OS 별 빌드 의존성 (openssl · readline) 이 "pyenv install 실패" 질문을 10 년간 양산
  • python-build-standalone (Gregory Szorc, 2019) 이 재배치 가능한 사전 빌드 바이너리를 만들었고 2024-12 Astral 이 프로젝트를 인수 — 다운로드 수 초면 끝
  • 패키지 · 가상환경 · 파이썬 버전이 한 툴 (uv) 안에 있으니 별도 버전 관리자가 필요 없어짐. asdf · conda 는 다중 언어 · 네이티브 생태계라는 다른 이유로 잔존

ruff 2022-08 → · 2023 부터 dominant

What
Rust 로 쓴 린터. flake8 + 플러그인 수십 개 · isort · pyupgrade · pydocstyle · autoflake · bandit 의 규칙을 900 개 이상 재구현해 한 번의 실행으로 끝냄.
Why now
  • flake8 (2010) 은 pyflakes + pycodestyle 래퍼일 뿐이라 기능은 플러그인 (bugbear · comprehensions · simplify …) 으로 흩어짐. 프로젝트마다 .flake8 + isort + pyupgrade + pre-commit 설정이 5–6 개 쌓임
  • 전부 Python 으로 쓰여 대형 레포에서 수십 초 — Charlie Marsh 의 "Python tooling could be much, much faster" (2022-08) 가 Rust 재작성으로 10–100× 를 보여주자 1 년 만에 pandas · FastAPI · Airflow 가 전환
  • 규칙 코드를 flake8 과 호환 (E501, B006, UP032 …) 시켜 이전 비용을 0 에 가깝게 만든 것이 결정적. 2023-10 포맷터까지 넣어 "린트 + 포맷 + import 정렬" 을 하나로

ruff format 2023-10 → · black (2018) 스타일 그대로

What

Why now
  • autopep8 (2011) 은 PEP 8 위반만 고치고, yapf (2015, Google) 는 옵션이 수십 개라 팀마다 스타일 논쟁이 계속됨

  • ruff 는 black 스타일을 바꾸지 않고 30× 빠르게 재구현. 2,772 개 Django 파일 중 34 개만 차이. "이미 합의된 스타일을 더 빠른 구현으로" — 수렴의 전형

pyright · ty · pyrefly 2019 → 2026 · mypy 이후, 아직 수렴 중

What
정적 타입 체커. 유일하게 "하나" 로 수렴하지 못한 카테고리 — CI 는 mypy, 에디터는 pyright (Pylance), 신규는 Rust 기반 ty · pyrefly.

pip · pip-tools · virtualenv 2008 · 2012 · 2007 → · uv 가 셋을 한 바이너리로

What
pip (2008) 설치기 · virtualenv (2007, Ian Bicking) 격리 · pip-tools (2012) 의존성 고정 (pip-compile). 셋을 따로 설치해 조합하는 것이 2012–2023 의 표준 세팅.
Why it faded
  • 셋이 각자 프로젝트라 lockfile 이 표준에 없었음 — requirements.txt 는 해석 결과일 뿐 플랫폼별 재현 불가. PEP 751 pylock.toml (2025-03) 까지 17 년
  • pip 20.3 (2020-11) 의 새 resolver 는 정확해졌지만 backtracking 이 분 단위 — Python 구현의 한계
  • uv 가 같은 CLI (uv pip install · uv venv · uv pip compile) 를 그대로 제공해 이전 비용 0, 캐시 없이 8–10× · 웜 캐시 80–115×
Replaced by
Numbers
PyPI 2026-09 월간: pip 407M · virtualenv 235M · pip-tools 12M (CI · 전이 의존 포함) · pip 26.2 (2026-08) 는 계속 릴리스 중 — 사라진 게 아니라 "직접 쓰는 사람" 이 줄어듦

easy_install 2004 – 2013 · setuptools 부속

What

  • wheel (PEP 427, 2012) 이 egg 를 대체하고 3.4 ensurepip (2014) 이 "pip 설치용" 쓰임까지 없앰. setuptools 가 2019 deprecate 후 제거

flake8 · pylint · isort · pyupgrade · bandit 2003 – 2022 · ruff 가 규칙을 재구현

What
각자 한 가지씩 — flake8 (2010) 스타일 + 오류 (pyflakes + pycodestyle 래퍼), pylint (2003) 추론 기반 검사, isort (2013) import 정렬, pyupgrade (2017) 구문 현대화, bandit (2015, OpenStack) 보안 패턴. 전부 Python 구현.
Why it faded
  • 다섯 개를 pre-commit 에 쌓으면 대형 레포에서 수십 초. ruff 가 전부 합쳐 1 초 미만 — 2023 년 한 해에 전환
  • flake8 플러그인 (bugbear · comprehensions · simplify …) 이 ruff 안에 같은 규칙 코드로 재구현되자 플러그인 저자들도 ruff 로 이동. isort 는 I, pyupgrade 는 UP, bandit 는 S 규칙으로
  • pylint 만 추론 기반 규칙이 남아 niche 생존 — ruff 가 PL 규칙으로 일부 흡수, 나머지는 타입 체커 영역으로 넘어감
