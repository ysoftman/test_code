$pyenv · uv · mise

세 도구가 맡는 범위는 서로 다릅니다. pyenv는 Python 버전만, uv는 Python 프로젝트 전체를, mise는 언어를 가리지 않는 런타임과 개발 환경을 다룹니다. 셋이 모두 겹치는 곳은 Python 인터프리터 설치와 버전 고정이고, uv와 mise는 가상환경, CLI 도구, 환경변수에서도 겹칩니다.

Apple M1 Max · macOS 27.0.1 uv 0.13.5 mise 2026.10.19 pyenv 2.8.13 (임시 설치로 측정) Python 3.14.8 hyperfine 2.0.0

01 · 역할세 도구가 하는 일

아래 표의 맨 위 ‘실행 방식’은 각 도구가 어떻게 동작하는지를 적은 줄이고, 그 아래에서 ‘겹침’ 표시가 붙은 줄은 두 도구 이상이 같은 일을 하는 기능입니다. 나머지 기능은 한 도구만 할 수 있어서 경쟁할 일이 없습니다.

기능 pyenv uv mise
실행 방식 bash로 만든 shim이 실행할 때마다 버전을 판단 shim 없음. uv run이 .venv를 동기화한 뒤 실행 mise activate로 PATH를 바꾸거나 shim 사용
Python 설치겹침 pyenv install 3.13
CPython 소스 컴파일 		uv python install 3.13
미리 빌드된 python-build-standalone 바이너리 		mise install python@3.13
uv와 같은 미리 빌드된 바이너리
디렉터리별 버전 고정겹침 pyenv local → .python-version uv python pin → .python-version mise use → mise.toml
가상환경겹침 pyenv-virtualenv 플러그인 uv venv, 프로젝트마다 자동 .venv _.python.venv (uv가 있으면 uv로 생성)
Python CLI 도구겹침 — uv tool install, uvx pypi: 백엔드 (옛 이름 pipx:)
의존성 해석, lockfile — uv add, uv.lock —
다른 언어 런타임 — — node, go, java, terraform …
환경변수겹침 — uv run --env-file [env] 섹션
task 실행 — — mise run

02 · 측정벤치마크

hyperfine으로 같은 명령을 반복 실행해 평균과 표준편차를 냈습니다. pyenv는 이미 지웠으므로 임시 디렉터리에 pyenv 2.8.13을 받아, mise와 uv가 쓰는 것과 같은 Python 3.14.8을 연결해 쟀습니다. 측정 당시 이 머신에서는 다른 가상 머신이 함께 돌고 있었습니다. 각 측정 단계를 시작할 때 기록한 load average(1분)는 4.1–9.9 사이였고, 마지막 pyenv 소스 컴파일 직후에는 6.5 정도였습니다. 아무 일도 하지 않는 /usr/bin/true도 실행에 14–18 ms가 걸렸지만 CPU 시간은 약 1.5 ms였습니다. 대부분이 기다린 시간이라, 짧은 명령은 CPU 시간 차트를 따로 실었습니다. 막대에 마우스를 올리거나 포커스하면 자세한 값이 나옵니다.

uv mise pyenv 표준 도구 (python, pip)
전체 측정값 표
측정 대상 평균 중앙값 ± σ 최소–최대 횟수

시간은 wall-clock 기준입니다(‘인터프리터 시작: CPU 시간’ 행만 user + sys CPU 시간). 패키지 설치와 인터프리터 설치는 네트워크 상태에 따라 크게 달라질 수 있습니다.

03 · 정리권장 구성

인터프리터를 설치하는 도구가 여럿이면 어느 Python이 실행되는지 헷갈리기 쉽습니다. 역할을 두 층으로 나누고 pyenv는 쓰지 않습니다.

mise
  • 전역 python3와 node, go 같은 런타임
  • 디렉터리별 환경변수와 task
  • 전역 설정은 ~/.config/mise/config.toml
uv
  • 프로젝트 의존성과 uv.lock, .venv
  • black 같은 단독 CLI는 uv tool install
  • 프로젝트별 Python은 .python-version
# 프로젝트
uv init --python 3.12 myproj && cd myproj   # .python-version 과 requires-python 을 함께 3.12 로
uv add fastapi uvicorn
uv add --dev pytest
uv run pytest            # .venv 생성과 동기화가 자동으로 됨

# 단독 CLI 도구
uv tool install black
uv tool upgrade --all

# 의존성이 있는 단일 스크립트 (PEP 723)
uv init --script foo.py
uv add --script foo.py requests
uv run foo.py

pyenv 명령을 uv로 바꾸면

pyenv uv
pyenv install 3.12 uv python install 3.12
pyenv versions uv python list --only-installed
pyenv global 3.14 uv python install 3.14 --default (python3 실행 파일), uv python pin --global 3.14 (uv 명령의 기본 버전)
pyenv local 3.12 uv python pin 3.12 (프로젝트 안에서는 requires-python 범위 안의 버전만)
pyenv shell 3.12, pyenv exec uv run --no-project --python 3.12 <cmd> (--no-project 없이 프로젝트 안에서 쓰면 .venv를 그 버전으로 다시 만듦)
pyenv uninstall 3.12.0 uv python uninstall 3.12.0
pyenv virtualenv + activate 자동 .venv + uv run
전역 pip install black uv tool install black
전역 pip install requests uv add requests 또는 uv run --with requests

이 머신은 mise Python이 PATH 앞쪽에 있어서, uv python install --default로 만든 ~/.local/bin/python3보다 mise 쪽이 먼저 실행됩니다. 전역 python3는 mise에 맡기는 편이 단순합니다.

04 · 경로어디에 설치되나

무엇 경로
uv add, uv sync <프로젝트>/.venv/lib/python3.X/site-packages
uv tool install ~/.local/share/uv/tools/<도구>/, 실행 파일은 ~/.local/bin
uvx, uv run --with ~/.cache/uv 안의 임시 환경
uv가 받은 Python ~/.local/share/uv/python
uv 캐시 (측정 당시 38 GB) ~/.cache/uv, venv에는 APFS clone으로 복제
mise Python ~/.local/share/mise/installs/python/<버전>
pip install (현재 셸) mise Python 3.14.8의 site-packages. mise가 Python을 새 버전으로 올리면 새 버전에는 없음

05 · 방법측정 방법

사용한 명령 
# 준비: 임시 pyenv 에 같은 Python 을 'bench' 로 연결, mise 바이너리를 python3 로 링크
git clone --branch v2.8.13 https://github.com/pyenv/pyenv $W/pyenv
ln -s $PY_PREFIX $W/pyenv/versions/bench && pyenv global bench && pyenv rehash
ln -s $MISE $W/shim/python3
uv init --bare proj && uv python pin --project proj $PY && uv add --project proj requests

# 시작 오버헤드 (hyperfine -N -w 5 -r 30)
/usr/bin/true
$PY -c pass
$W/pyenv/shims/python -c pass
$W/shim/python3 -c pass
uv run --project proj python -c pass

# venv 생성 (-w 2 -r 10, 매 회 디렉터리 삭제)
$PY -m venv v1                 # pip 포함
uv venv --seed v2              # pip 포함
$PY -m venv --without-pip v3
uv venv v4

# 패키지 설치: requests rich pydantic httpx 를 빈 venv 에
pip install --no-compile …     # pyc 없음
uv pip install …               # pyc 없음 (uv 기본)
pip install …                  # pyc 생성 (pip 기본)
uv pip install --compile-bytecode …
# cold: pip 은 --no-cache-dir, uv 는 매 회 캐시 삭제. 네 명령을 1회씩 번갈아 5바퀴, 짝수 바퀴는 순서를 뒤집음
# warm: 캐시를 남긴 채 -w 1 -r 5

# 인터프리터 설치 (매 회 설치 디렉터리 삭제, 두 명령을 번갈아 5바퀴, 짝수 바퀴는 순서를 뒤집음)
uv python install --no-bin --install-dir $W/uvpy 3.13.17
mise install python@3.13.17    # MISE_DATA_DIR 등은 미리 export
python-build 3.13.17 $W/pyb    # pyenv install 과 같은 소스 빌드, 1회

전체 절차는 bench.sh에 있고, 결과 원본과 단계별 load average는 같은 디렉터리의 out/에 있습니다. 차트 데이터와 결론 문장의 수치는 gen_charts.py가 out/에서 만듭니다. 명령 앞에 env를 붙이면 프로세스가 하나 더 떠서 시간이 섞이므로, 캐시 경로 같은 환경변수는 미리 export했습니다. 네트워크가 섞이는 측정은 같은 시간대에 번갈아 재서 회선 상태 차이를 줄였습니다.
