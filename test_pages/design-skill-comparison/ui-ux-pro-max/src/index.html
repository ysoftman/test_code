    기능

    에이전트 설치부터 Slack 알림까지

    로그 파이프라인을 직접 조립하지 않아도 됩니다. 네 가지 기능이 하나의 저장소와 하나의 쿼리 언어를 공유합니다.

    01 · 수집

    에이전트 하나로 모든 로그를

    DaemonSet 또는 systemd 서비스로 배포되는 경량 에이전트가 컨테이너 stdout, journald, 파일 로그를 모아 압축한 뒤 오브젝트 스토리지에 저장합니다. 인덱스는 레이블에만 걸어 저장 비용을 낮춥니다. 

    # values.yaml
agent:
  sources: [kubernetes, journald, file]
  storage: s3://team-logs/driftlog
  compression: zstd

    02 · 검색

    익숙한 LogQL 스타일 쿼리

    레이블로 범위를 좁히고 |=, |~ 필터로 본문을 찾습니다. Grafana 데이터소스로 연결하면 기존 대시보드에서 그대로 조회합니다. 

    sum by (app) (
  count_over_time(
    {namespace="prod"} |= "error" [5m]
  )
)

    03 · 라이브 테일

    배포 직후의 로그를 실시간으로

    쿼리 조건 그대로 새 로그를 스트리밍합니다. 브라우저에서도, CLI에서도 tail -f처럼 지켜보세요. 

    $ driftlog tail '{app="checkout"}'
14:21:07 INFO  order placed id=8f2c
14:21:08 WARN  retry payment attempt=2
14:21:09 ERROR payment timeout 3000ms

    04 · 알림

    에러가 급증하면 Slack으로

    평소 대비 에러 비율이 튀면 해당 쿼리 링크와 함께 Slack 채널로 알립니다. 임계값과 알림을 받지 않을 시간대는 팀별로 정합니다.

    #oncall-backend · Driftlog 알림 봇 · 14:20

    [ERROR 급증] checkout · 2분간 312건

    직전 1시간 평균 대비 8.4배 · {app="checkout"} |= "timeout"

    FAQ

    자주 묻는 질문

    자체 호스팅도 가능한가요?
    네. Enterprise 플랜은 고객의 VPC나 온프레미스 쿠버네티스 클러스터에 Helm 차트로 설치할 수 있습니다. Free·Team 플랜은 Driftlog 클라우드에서 운영되며, 수집 에이전트만 고객 환경에서 동작합니다.
    지금 쓰는 Loki나 Vector와 함께 쓸 수 있나요?
    네. Vector의 HTTP sink나 Loki push API 형식으로 그대로 보낼 수 있어 기존 파이프라인을 바꾸지 않아도 됩니다. 쿼리 문법도 LogQL과 거의 같아 기존 쿼리 대부분을 재사용할 수 있고, Grafana에는 Loki 호환 데이터소스로 연결됩니다.
    로그 데이터는 어디에 저장되나요?
    클라우드 플랜의 로그는 서울 리전 오브젝트 스토리지에 암호화되어 저장됩니다. Enterprise 플랜은 고객이 소유한 S3 호환 버킷을 저장소로 지정할 수 있어, 데이터가 고객 계정 밖으로 나가지 않습니다.
    하루 수집 한도를 넘으면 어떻게 되나요?
    한도의 80%와 100%에 도달하면 이메일과 Slack으로 알려 드립니다. Free 플랜은 한도를 넘으면 다음 날 0시(KST)까지 수집을 멈추고, Team 플랜은 수집을 멈추지 않고 초과분을 다음 달 청구서에 GB 단위로 합산합니다. 장애 중에 로그가 끊기는 일은 없습니다.
